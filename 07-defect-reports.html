DEF-OHRM-001 — Intermittent HTTP 500 on the login page

Field Detail
Defect ID DEF-OHRM-001
Title /web/index.php/auth/login intermittently returns HTTP 500, blocking all access
Module Login (platform-wide impact)
Steps to Reproduce 1. Perform several successive login/logout cycles (observed during automated regression, ~10–20 requests over a few minutes) 2. Navigate to the login URL 3. Intermittently the server responds 500 Internal Server Error instead of the login form
Expected Result Login page returns HTTP 200 and renders the credential form on every request
Actual Result Sporadic 500 Internal Server Error; the page recovers on retry after a few seconds
Severity Critical
Priority P2
Environment OrangeHRM Open Source demo (opensource-demo.orangehrmlive.com), observed 2026-07-20 during Cypress 15.18.1 headless regression (Electron 136), Windows 11; reproducible independent of browser
Evidence [screenshot: cypress-run-500-login.png] · CI log excerpt: cy.visit() failed ... The response we received from your web server was: > 500: Internal Server Error (full-suite run #2, 2026-07-20)
Reproducibility Intermittent (~1 in 10–15 page loads under repeated authentication activity)
Status Open — reported; suspected infrastructure/rate-limit behaviour on the shared tenant, needs server-side log correlation

DEF-OHRM-002 — Unhandled JavaScript exception during logout navigation

Field Detail
Defect ID DEF-OHRM-002
Title Unhandled TypeError: Cannot read properties of undefined (reading 'response') thrown when navigation cancels in-flight dashboard requests
Module Dashboard / global SPA error handling
Steps to Reproduce 1. Log in as Admin 2. Land on Dashboard (widget XHRs begin loading) 3. Immediately open the user menu and click Logout 4. Observe the browser console
Expected Result Cancelled/401'd XHRs during navigation are handled gracefully; no uncaught exceptions reach the console
Actual Result Dashboard widget calls (api/v2/buzz/feed, api/v2/dashboard/shortcuts) return 401 mid-teardown and the response interceptor throws an uncaught TypeError; thrown twice per occurrence
Severity Low
Priority P3
Environment Same as DEF-OHRM-001; observed consistently on logout in Chromium-family browsers
Evidence [screenshot: logout-uncaught-typeerror.png] (captured by Cypress on TC-LOG-008, run #1, 2026-07-20) — console shows (uncaught exception) TypeError: Cannot read properties of undefined (reading 'response') (2)
Reproducibility Consistent when logout occurs while dashboard XHRs are in flight
Status Open

DEF-OHRM-003 — Leave Apply accepts an invalid date range when dates are typed manually

Field Detail
Defect ID DEF-OHRM-003
Title "To" date earlier than "From" date is accepted on Apply Leave when entered via keyboard; validation fires only for calendar-widget selection
Module Leave > Apply
Steps to Reproduce 1. Log in as Admin (leave entitlement present) 2. Leave > Apply 3. Select a leave type 4. Type From Date 2026-08-10 and To Date 2026-08-08 directly into the fields (do not use the calendar popup) 5. Click Apply
Expected Result Validation error ("To date should be after from date"), submission blocked — as correctly happens when dates are picked from the calendar widget
Actual Result The form submits; a leave request with an inverted date range is created and appears in My Leave with a negative/zero duration
Severity High
Priority P2
Environment OrangeHRM demo, Chrome 138 / Firefox 128, verified in exploratory follow-up after automated TC-LEA-004 failed on this path
Evidence [screenshot: leave-inverted-range-accepted.png] · [screenshot: my-leave-negative-duration-row.png] · failing case: TC-LEA-004 (both frameworks)
Reproducibility Consistent via keyboard entry; not reproducible via calendar picker
Status Open

DEF-OHRM-004 — Employee name header shows stale value after Personal Details edit

Field Detail
Defect ID DEF-OHRM-004
Title After editing an employee's last name in Personal Details, the page header keeps showing the old name until a manual reload
Module PIM > Employee Personal Details
Steps to Reproduce 1. Log in as Admin 2. PIM > open any employee 3. In Personal Details, change Last Name and click Save 4. Observe the "Successfully Updated" toast 5. Compare the name shown in the left header panel with the saved value
Expected Result The header reflects the new name immediately after the save is confirmed
Actual Result Header continues to show the previous name; the grid and header show the new value only after a full page reload
Severity Medium
Priority P3
Environment OrangeHRM demo, found during exploratory testing around TC-PIM-007 (which asserts field persistence via reload and therefore passes)
Evidence [screenshot: pim-stale-header-after-save.png] · [screen recording: pim-header-refresh.mp4]
Reproducibility Consistent
Status Open — note: not covered by a scripted case; RTM gap logged in the closure report with a proposed TC-PIM-013
