4. Lessons learned (retrospective highlights)

  1. The shared tenant was the single biggest cost driver — session caching with validation, per-run unique data, and bounded 500-retries were all forced by it, and all three are now durable framework strengths.
  2. Dual-framework parity was cheap once the design was tool-agnostic — identical page-object interfaces and shared TC IDs made cross-tool review mechanical.
  3. Negative paths need input-mode coverage — DEF-OHRM-003 only surfaces on keyboard entry; future date-field cases will always exercise both picker and typed input.
  4. Exploratory testing still earns its place — the two most interesting AUT defects (003, 004) were found at the edges of scripted flows.

5. Sign-off recommendation

Recommendation: CONDITIONAL SIGN-OFF.

  • Sign off now: Login, Admin, PIM, Dashboard modules — fully executed, 100% pass, stable across repeated runs, defects in these areas are Low/Medium display-and-hygiene issues that do not compromise data integrity.
  • Withhold sign-off: Leave module — pending (a) fix and re-verification of DEF-OHRM-003 (data-integrity defect), and (b) execution of the 2 blocked cases in a post-reset window.
  • Platform condition: DEF-OHRM-001 must be root-caused on production-representative infrastructure before any go-live decision; on the shared demo it is unresolvable by this engagement.

Closure actions on approval: cut release tag v1.0.0, freeze RTM, archive CI reports as build artifacts, add TC-PIM-013 to the backlog for the next cycle.
